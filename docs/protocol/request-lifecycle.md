# Request Lifecycle Protocol

این سند قرارداد دقیق ارتباطی و ساختار داده بین Request Network و Response Network را تعریف می‌کند. 
در ریفکتور Reliability، تمامی اجزا باید دقیقاً از این ساختار پیروی کنند.

## 1. ساختار داده درخواست (Request)

هر درخواست یا رکورد در زمان تبادل باید شامل فیلدهای کلیدی زیر باشد:

- `request_id`: شناسه یکتای درخواست (UUID).
- `batch_id`: شناسه دسته‌ای که این درخواست در آن صادر شده است.
- `attempt`: شماره تلاش فعلی برای اجرای این درخواست (جهت پیاده‌سازی مکانیزم Retry).
- `created_at`: زمان ایجاد درخواست.

## 2. ساختار داده فایل (File)

هر فایلی که در شبکه منتقل می‌شود (اعم از درخواست‌ها یا نتایج) باید دارای متادیتا و ساختار زیر باشد:

- `file_id`: شناسه یکتای فایل تبادلی.
- `batch_id`: شناسه دسته‌ای که فایل به آن تعلق دارد.
- `file_type`: نوع فایل (مانند `requests`, `results`, `audit_acks`).
- `record_count`: تعداد رکوردهای موجود در فایل (جهت صحت‌سنجی).
- `checksum`: هش (Hash) محتوای فایل برای اطمینان از یکپارچگی داده و جلوگیری از خرابی.
- `schema_ver`: نسخه ساختار داده (برای پشتیبانی از نسخه‌های آتی بدون ایجاد Breaking Change).
